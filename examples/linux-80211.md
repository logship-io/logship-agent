# Linux IEEE 802.11 capture

Merge [linux-80211-config.json](linux-80211-config.json) into the agent configuration. The source is inactive when absent. Configure one dedicated, dual-band, monitor-capable adapter by its Linux interface name. Upload through another interface. Stop any network manager or supplicant from controlling this adapter (NetworkManager: `nmcli device set wlan1 managed no`), and ensure no other interface on the same physical radio is in use.

Install `iw`, `iproute2`, and libpcap (Debian/Ubuntu: `apt-get install iw iproute2 libpcap0.8`). The shipped container includes these packages. Supported library names are `libpcap.so.0.8`, `libpcap.so.1`, and `libpcap.so`. Capture requires 64-bit Linux. Run as root, or arrange `CAP_NET_ADMIN` and `CAP_NET_RAW` for the agent and its iw/ip subprocesses. Containers require host networking and these capabilities: `--network host --cap-add NET_ADMIN --cap-add NET_RAW`. The host supplies the adapter driver and regulatory domain.

The source changes the adapter to monitor mode and passively hops across enabled 2.4 GHz and 5 GHz frequencies. It sends no probes and changes no regulatory settings. `frequenciesMHz` optionally restricts the list, for example `[2412, 2437, 2462, 5180, 5200]`; unsupported or disabled requested frequencies cause a source error. DFS/no-IR frequencies are attempted for passive reception but driver restrictions may prevent tuning. Failed frequencies are skipped until the next sweep. The default dwell is 250 ms per successfully tuned frequency; command overhead adds to sweep duration.

One radio receives only one frequency at a time. Frames on other channels are missed; driver, capture-buffer, and event-buffer losses remain possible. Wide-band and nonstandard driver behavior require hardware validation. Duplicates and retransmissions are retained. Dense environments can produce substantial ingestion volume; restrict frequencies or provision the existing output buffer as needed.

## Schema

Each decoded frame is sent to `Linux.80211.Management` (or `schema`) with its capture timestamp. Existing buffering and upload apply. Values are scalar strings, integers, and booleans.

| Fields | Meaning |
| --- | --- |
| `machine`, `Interface` | Collector host and capture interface |
| `FrameType` | `Beacon`, `ProbeRequest`, or `ProbeResponse` |
| `SourceMac`, `DestinationMac`, `Bssid` | Observed lowercase colon-separated addresses; probe BSSID may be a wildcard |
| `SequenceNumber`, `FragmentNumber`, `Retry`, `FrameLength` | Frame metadata; length excludes radiotap and reported trailing FCS |
| `FrequencyMHz`, `Channel`, `Band`, `SignalDbm` | Optional receive metadata from radiotap; omitted when unavailable |
| `AdvertisedChannel` | Optional DS parameter channel, separate from receive frequency |
| `Ssid`, `SsidHex` | Optional text and lossless bytes; invalid UTF-8 is replaced in text only |
| `WildcardProbe`, `HiddenSsid` | Empty SSID indication for requests or beacons/responses respectively; omitted if SSID element is missing |
| `BeaconIntervalTu`, `CapabilityFlags`, `Privacy` | Beacon/response fixed fields; privacy bit does not identify WPA version |
| `InformationElementsHex` | Original information elements |

Raw MAC addresses and SSIDs are retained. MAC randomization means observations do not reliably identify a physical device. Malformed, truncated, protected, unsupported, and explicitly bad-FCS frames are skipped. Detailed security-suite classification and packet-file storage are not implemented.

## Operation

Source errors are logged and retried after 30 seconds without stopping other sources. Metrics in `Logship.Agent.80211` report `logship.agent.80211.capture_drops`, `invalid_frames`, `capture_failures`, and `hop_failures`. Capture drops are sampled every five seconds from libpcap; existing event-buffer metrics report ingestion overflow.

Shutdown and failed setup attempt to restore original adapter type, known frequency, and up/down state within 20 seconds. Reconnection is not guaranteed. Crashes, forced termination, removal, or driver command failures can prevent restoration; check the adapter manually after such events.

Hardware acceptance: verify uploads of known beacons on both bands, probe requests and responses, repeated frequency changes, and normal shutdown restoration. Test permission failures and unplug/replug recovery. These checks require a real Linux monitor-capable adapter; automated parser/lifecycle tests use fixtures and fakes.
